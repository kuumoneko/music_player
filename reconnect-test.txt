Auto-Reconnection Implementation - KuumoApp

SUMMARY OF CHANGES MADE:
========================

1. BOTH FRONTENDS (WinUI & Avalonia) NOW HAVE AUTO-RECONNECTION LOGIC:
   - app-winui/KuumoApp/Services/RpcClient.cs  
   - app-avalonia/KuumoApp/Services/RpcClient.cs

2. KEY IMPLEMENTATION DETAILS:
   
   A. Connection Tracking:
      - Added _lastEndpoint field to remember which endpoint was connected to
      
   B. Reconnection Logic:
      - Implemented ScheduleReconnect() with exponential backoff algorithm
      - Delay calculation: min(1000 * 2^attempts, 30000ms) = max 30 seconds between attempts
      - Proper cleanup of timers on disposal
   
   C. Disconnection Handling:
      - Modified ReceiveLoopAsync to detect when connection is lost 
      - Triggers reconnection process automatically on disconnection
      - Resets attempt counter only on successful reconnect
    
   D. Resource Management:
      - Timer disposed properly during Dispose()
      - CancellationToken handling for graceful shutdowns

3. BEHAVIOR:
   - When network drops or backend restarts:
     -> Client detects disconnect in receive loop
     -> Automatically starts retrying with increasing delays
     -> Max delay capped at 30 seconds
     -> On success, resets retry count and continues normal operation
   - No user intervention needed after connectivity returns

4. TECHNICAL APPROACH:
   - Uses System.Threading.Timer for scheduled retries  
   - Implements proper cancellation tokens for clean shutdowns
   - Thread-safe operations using SemaphoreSlim locks
   - Maintains all existing functionality while adding new features

This implementation resolves the issue where users had to manually restart KuumoApp after internet outages.
